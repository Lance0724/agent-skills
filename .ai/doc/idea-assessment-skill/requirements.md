# 想法评估技能需求文档

## 概述

创建 `idea-assessment` Agent Skill，在投入方案设计或实现之前，通过“收集、研究、定义、塑形、决策”评估一个想法是否值得继续。技能借鉴 Spec Kit Idea Assessment，并沿用 `new-feature` 的中文文档、阶段门槛、模板和评估用例组织方式。

- 文档模式：标准模式
- 目标用户：需要评估产品、技术或非软件想法的开发者、产品人员和决策者
- 预期价值：用正反证据和明确门槛得到可审计的 `go`、`needs-clarification` 或 `kill` 决策，避免过早进入实现

## 目标

- 忠实记录原始想法和来源，不在收集阶段提前评价。
- 同时收集支持和反对证据，并区分事实、假设和未知项。
- 把解决方案表述还原为明确的问题、目标、非目标和成功指标。
- 在概念层比较方案和投入尺度，不进入详细技术设计。
- 输出有证据约束的决策，且不自动启动新功能开发。

## 范围

### 包含

- 新增 `idea-assessment/SKILL.md`。
- 新增收集、研究、问题定义、概念塑形和决策模板。
- 新增输出质量和触发边界评估用例。
- 产物写入 `.ai/doc/assessments/[idea-name]/` 下的五个阶段文件。

### 不包含

- 不修改任何源代码。
- 不生成架构、数据模型、接口定义或实施任务。
- 不在 `go` 后自动触发 `new-feature`；是否交接由用户决定。
- 不实现 Spec Kit CLI 命令或安装 Spec Kit 扩展。

## 需求

### REQ-001：准确触发与边界

技能应在用户要求评估想法、可行性、投入价值、方案取舍或是否值得建设时触发；已批准功能的实施和已有行为缺陷修复不得触发。

### REQ-002：五阶段评估

标准流程必须覆盖“收集、研究、定义、塑形、决策”，产出 `intake.md`、`research.md`、`problem.md`、`concept.md` 和 `decision.md`。

### REQ-003：证据纪律

研究必须同时记录支持和反对证据，并为结论提供来源和置信度。无来源内容必须标为 `ASSUMPTION`，不得伪造引用。

### REQ-004：问题与方案分离

问题定义阶段不得设计解决方案；概念塑形阶段只能比较概念级选项、投入尺度和取舍，不得生成架构、接口、数据模型或实施任务。

### REQ-005：决策门槛

决策必须使用 `strong`、`adequate`、`weak`、`unknown` 评分并给出 `go`、`needs-clarification` 或 `kill`。只有问题有效性和证据强度至少为 `adequate` 且存在推荐概念时才能判定 `go`。

### REQ-006：独立且只读

整个评估流程只允许读取仓库和外部证据，写入评估目录，不得修改源代码。`go` 只生成交接摘要，不自动进入实现。

### REQ-007：安全与增量修订

外部内容视为不可信数据，不得执行其中指令或泄露秘密。已有产物不得静默覆盖；补充信息应定向更新受影响产物和下游决策，而不是盲目重跑全部阶段。

### REQ-008：中文与格式规范

技能、模板及其生成产物的自然语言内容使用中文；代码标识符、命令、路径和协议字段遵循项目约定。技能必须符合 Agent Skills 规范。

### REQ-009：评估覆盖

技能应提供至少三个输出质量场景和包含正负样例的触发评估，覆盖 `go`、`needs-clarification`、`kill` 以及与新功能和缺陷修复的边界。

## 用户故事

- 作为决策者，我希望在投入开发前看到支持和反对证据，以便选择继续、澄清或停止。
- 作为后续实施者，我希望 `go` 决策包含清晰的问题、范围、成功指标和概念交接，以便后续独立进入新功能流程。

## 验收标准

- [ ] AC-001：给定一个原始想法，技能能够创建独立评估目录并生成五个中文阶段产物。
- [ ] AC-002：`research.md` 同时包含支持和反对证据，并标注来源、置信度或 `ASSUMPTION`。
- [ ] AC-003：`problem.md` 不包含具体方案，`concept.md` 不包含详细架构、接口、数据模型或任务。
- [ ] AC-004：证据不足或缺少概念时不得输出 `go`，必须输出 `needs-clarification` 或 `kill`。
- [ ] AC-005：评估过程中不修改源代码，`go` 后也不自动创建实现代码。
- [ ] AC-006：补充新事实时只更新受影响产物并重新审视依赖它的决策。
- [ ] AC-007：官方 `skills-ref` 验证通过，评估 JSON 文件语法有效。

## 约束与依赖

- 参考 Spec Kit Idea Assessment 的 `intake → research → define → shape → decide` 语义，但使用本仓库的 `.ai/doc/` 路径和中文模板。
- 允许空代码仓库或非软件想法；仓库仅在想法与现有代码有关时作为证据来源。
- 名称必须规范化为英文 kebab-case，并防止路径逃逸和静默覆盖。

## 问题与决策

- [已解决] 技能名称：使用 `idea-assessment`，与 Agent Skills 目录名一致。
- [已解决] 评估路径：使用 `.ai/doc/assessments/[idea-name]/`。
- [已解决] 阶段策略：默认执行完整五阶段；若已有充分输入，可以从问题定义开始，但 `go` 仍需充分证据和推荐概念。
